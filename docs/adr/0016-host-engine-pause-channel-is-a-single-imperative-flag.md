# Host→Engine pause is a single imperative flag, not part of World Config

ADR-0011 reserved an imperative Host→Engine command channel (pause/resume, forced movement) for "whenever a CG/cutscene feature, which genuinely needs to take control from the Player, is actually designed" — this is that moment. We considered keeping the Engine purely config-driven (ADR-0001) by threading a `paused` field through World Config instead of adding a new call, but rejected it: World Config is read once at construction, and a Cutscene needs to flip pause on and off mid-session without reconfiguring the Engine. Instead the Engine gains one small piece of new runtime state — a boolean set via an imperative `setPaused(bool)` call — checked at the top of `handleMovementInput` and `handleInteractInput` before either reads input. This is a narrow, deliberate exception to ADR-0001's "stateless, config-driven" Engine: the Engine still owns no *content* (Flags, Dialogue, and Cutscene definitions all stay Host-side per ADR-0008), just the single fact of whether input is currently live.
