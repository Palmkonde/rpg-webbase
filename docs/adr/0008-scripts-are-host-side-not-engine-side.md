# Scripts run on the Host, not inside the Engine

We're adding Scripts — Host-authored code that reacts to an Interaction or a Map-entering Transition and produces Dialogue. The obvious reference point is Unity, where a script is attached to a GameObject and runs *inside* the engine. We reject that shape here: ADR-0001 already commits the Engine to being a stateless, generic renderer with zero knowledge of what an Entity, Interaction, or Map represents, and letting it also execute Host-owned game logic (dialogue content, per-Student Flags) would reintroduce exactly the coupling ADR-0001 was written to avoid. A Script is ordinary Host-side code triggered by an Engine Event (`interacted`, `transitioned`); the Engine never knows Scripts exist, gains no new API surface for them, and Host-side tooling that needs to know which Entities exist reads the authored Tiled map directly rather than the Engine exposing an entity catalog.
