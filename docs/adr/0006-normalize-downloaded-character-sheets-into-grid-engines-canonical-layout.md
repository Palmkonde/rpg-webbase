# Normalize downloaded character sprite sheets by hand into grid-engine's canonical layout; team-authored sheets are drawn correctly from the start

Character sprite sheets found online (e.g. an Undertale rip used as a test asset, or a generator export) each arrange frames differently, and none reliably match grid-engine's own default character-animation model, which expects a fixed grid: one row of 3 frames (left-foot/standing/right-foot) per cardinal direction. Rather than teaching the Engine to read an arbitrary layout per character, we normalize each downloaded sheet by hand — crop/rearrange it in an external image tool into that canonical grid shape — before it's ever loaded, and commit the result alongside the original raw download (`raw.*` + a normalized file per character, under `assets/sprites/characters/<name>/`) so a bad crop can be redone without re-sourcing the asset. A sheet the team draws itself skips this step entirely by being authored directly in the canonical layout. Where a source sheet has no real art for one or more directions, the person normalizing it duplicates frames from an available direction into the missing slot(s) at this same authoring step — grid-engine's `WalkingAnimationMapping` requires real frame numbers for all four cardinal directions regardless, so this keeps the Engine's runtime code identical for every character whether its source was complete or not.

We considered instead building a generic frame-mapping config per character (each source's native frame positions described as data, similar to how Tiled's per-tile `animation` metadata already drives tile animation — see ADR-0003). We rejected it: unlike Tiled tilesets, arbitrary internet-sourced character rips don't come with any structured layout data to key off, a normalization pass on the raw pixels is happening either way, and this repo will only add a new character sheet rarely — building configurable-layout tooling now is speculative generality for a one-off manual task.
