# Entity rendering splits into Character Entities and Prop Entities, not one Character pipeline for everything

Entities have no visual representation in the live game today — only the Player renders (a Tiled object's `gid`, like Campfire's, is Tiled-editor-preview only, never drawn by the running game). Giving Entities a picture at all could mean forcing every one through the Player's existing Character pipeline (ADR-0006's four-direction sprite-sheet normalization — even a static campfire would need four duplicated "walking" directions it never uses), or splitting rendering by whether an Entity actually needs to walk. We chose to split: a Character Entity has a Character and is registered/animated exactly like the Player, making it eligible for a Cutscene's Movement or Follow step (the target #26/#28 already assume exists); a Prop Entity has no Character and is drawn directly from its Tiled object's own tile — no sprite-sheet prep, no grid-engine registration, nothing to normalize.

We considered the uniform-pipeline approach (one system, everything gets a Character) for the sake of having only one rendering code path. We rejected it: forcing a static prop through direction-normalization it will never use is busywork with no payoff, and a Prop Entity's Tiled-authored tile already gives the designer a picture for free, the same way any other painted tile does.
