# Dialogue portraits are a standalone asset type, not part of the character-spritesheet pipeline

Portrait art for the Dialogue overlay could have reused `assets/sprites/characters/<name>/` and ADR-0006's raw/normalized walk-cycle pipeline, since that's the only existing convention in this repo for character-associated art. We rejected that: a Portrait is a static per-Expression illustration with no grid/frame/animation concerns, and a Dialogue line's Speaker need not correspond to any placed Entity or Player character at all (e.g. a narrator) — forcing every Portrait through a pipeline built for animated walk-cycle spritesheets would couple two unrelated concerns and leave a narrator with no path to a Portrait. Portrait art instead lives in its own independent location, keyed directly by whatever string a Script uses as `speaker`, with no relationship to a character's spritesheet folder even when both exist for the same named character.
