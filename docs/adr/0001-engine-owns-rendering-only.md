# Engine is a framework-agnostic module; Host owns state and content

The Engine (rendering, grid movement, Transitions, generic Entity Interaction) lives in a framework-agnostic TypeScript package with no Next.js/React dependency, and is stateless — it takes a World Config in and emits Engine Events out. All game content and state (dialogue, quests, XP, progression, unlocks) is owned by the Host, currently a thin Next.js app in this playground, backed by the main platform's database once integrated. We considered building dialogue/quests/state directly into the Engine, since "RPG gamification" usually implies them, but rejected it: this Engine is meant to be lifted into a separate monorepo as a reusable package, and baking in course-specific logic or a framework dependency would tie it to this one integration instead of being portable. This keeps the Engine a deep module — Phaser and grid-engine's complexity hidden behind one small config/event interface — testable without a browser, and the planned Ink-language dialogue integration will live entirely in the Host.
