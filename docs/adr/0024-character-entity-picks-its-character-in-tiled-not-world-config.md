# A Character Entity's Character is chosen in Tiled, not World Config

The Player's own Character (and spawn position) is deliberately kept out of Tiled and set by World Config instead — Tiled's own rejected `spawn_key` property is the established precedent for this (ADR-0012). A Character Entity's Character could have followed that same pattern: a World Config mapping from `entityId` to `characterId`. We chose the opposite — `characterId` is a Tiled Custom Class property on the Entity object itself (an enum listing `catalogs.ts`'s ids, so the designer picks from a dropdown rather than hand-typing a string) — because unlike the Player's Character, which can plausibly vary per Student, a Character Entity's look is a map-authoring decision: the designer placing a Guard wants to pick what the Guard looks like right there, without a corresponding Host code change for every placement. This is a deliberate departure from the Player's pattern; a future reader shouldn't "fix" it to match.

This requires a `test_map.tiled-project` file defining the `Entity` Custom Class's properties (`characterId` enum, plus an optional `facing` property defaulting to `'down'` for a Character Entity's idle orientation) — none exists in the repo yet, despite ADR-0010 calling for one. Creating it is part of this same piece of work.
