# Dialogue text goes through a string table, not a reopened ADR-0009

Content authors who aren't comfortable writing TypeScript need to edit and translate Dialogue text — the exact "non-programmer authoring becomes a real requirement" condition ADR-0009 named as its own trigger for reconsidering "TypeScript, not a parsed DSL." We're not reopening it yet: Dialogue line text resolves through a string-table layer (a locale-keyed text lookup a non-technical author can edit directly), while a programmer still authors each Script's branching structure in TypeScript. This solves the concrete pain — multi-language text and non-technical line editing — without ADR-0009's full cost. If the same author ever needs to build or rearrange the branching/choice structure itself, not just edit line text, that's the real trigger for reopening ADR-0009 toward a parsed DSL (e.g. the already-deferred Ink integration) — not something to fold into this string-table fix.
