# Scale the canvas with Phaser FIT and a fixed camera zoom, not a variable virtual resolution

The canvas was hardcoded at 640×480 with no Scale Manager configuration, so it never adapted to the browser window, and 32px tiles rendered too small at that fixed size. We adopt Grid Engine's own documented pattern: `Phaser.Scale.FIT` with `autoCenter: CENTER_BOTH` stretches a 960×540 (16:9) virtual resolution to fill whatever window the Host renders into, while the "tiles feel small" problem is solved independently by the camera — a fixed `setZoom(2)`, `startFollow(player, true)`, and per-Map `setBounds(...)` computed from that Map's own pixel dimensions. We considered `Phaser.Scale.RESIZE` (rejected — it grows the visible world area with screen size instead of just growing pixels, an inconsistency across devices) and `Phaser.Scale.ENVELOP` (rejected — crops the world rather than framing it), and considered a variable resolution/scale-factor instead of camera zoom as the fix for small tiles (rejected — it would need per-Map tuning, where zoom is a single Engine-wide constant Grid Engine already expects). The base resolution also moves from 4:3 to 16:9 so FIT doesn't letterbox on typical widescreen windows. Future Maps should be authored at roughly 480×270 world units or larger if they're meant to fill the frame edge-to-edge at this zoom.
