# Zone entries are dropped while the Engine is paused, not queued or nested

Refines `adr/0019` and `adr/0021`. A Zone reacts only to the Player's own movement. When a Cutscene walks the Player into a Zone (a Movement or Follow step), letting the Zone's Script run straight away breaks playback: a Zone Cutscene replaces the running one's handle, so the original waits forever on a click, and the inner one's `setPaused(false)` unfreezes the Player too early. We considered queueing the Zone's Script until the Cutscene ends, and nesting it inside the running Cutscene the way a Choice hand-off does. We rejected both. The Zone didn't trigger the Cutscene's walk and shouldn't hijack it, and nesting can't pause a Movement already in progress. So the Engine simply doesn't emit `zoneEntered` while `setPaused(true)` is in effect (`adr/0016`). The entry is dropped, not saved: its `runOnce` Flag isn't burned, and a Player left standing inside the Zone when control returns sets it off only by walking out and back in. The check lives in the Engine because the pause flag already means "the Host has taken control of the Player", and movement and interact input already obey it. The boot CG plays before the Engine is created, so spawn-inside-a-Zone (`adr/0022`) is unaffected.
