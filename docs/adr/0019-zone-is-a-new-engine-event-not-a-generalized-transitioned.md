# Zone is a new, separate Engine Event; it doesn't generalize or reopen `transitioned`

Designing Zone (a Player walking into an authored region triggers a Script) surfaced an obvious-looking simplification: since `transitioned`'s Map-entry trigger (ticket #13, not yet built) is also "the Player arrived somewhere and a Script should run," why not treat the whole Map as one implicit Zone and unify the two under one Engine Event? We considered this and rejected it: `transitioned` is an already-shipped, tested Engine Event (ADR-0004's "size the contract up front"), and reopening a shipped contract to fold in Zone's rectangle semantics would touch working code for a nicety, not a concrete need. Instead Zone gets its own new Engine Event, `zoneEntered`, coexisting alongside `transitioned` — the two share the same Script-lookup convention (see ADR-0020) so a future Map-entry Script and a Zone's Script are authored identically, but the Engine Event contract itself stays untouched. `CONTEXT.md`'s Transition/Map vocabulary already treats "crossing a Map's boundary" and "a region inside a Map" as separate concepts; this keeps the Engine Event contract aligned with that distinction rather than collapsing it for code-reuse's sake.
