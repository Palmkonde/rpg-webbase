# Zone activation isn't gated by World Config — it follows Entity/Portal's actual (not the spec's originally-aspirational) behavior

The spec's own "Contract" language for World Config says it controls "which of that Map's Tiled-authored Entities and Portals are currently active" — implying some Entities/Portals could be authored but inactive for a given Player. Checking the shipped code while designing Zone surfaced that this was never actually built: `collectEntities` returns every Entity on the loaded Map unconditionally, and `WorldConfig`'s real shape carries no entities/portals field at all. We considered treating Zone's design as the moment to retrofit real activation-filtering (since it's the "correct" reading of the original spec intent) and rejected it: that's a separate, larger change affecting Entities/Portals too, not something to build as a side effect of adding a third kind of Map object. Zone instead follows the de facto rule already governing Entities/Portals: every one authored on the currently-loaded Map is simply always live. A future ticket that actually builds World Config-gated activation would apply to all three kinds uniformly, not just Zone.
