# Size the Engine Event contract for tickets 03–05 up front, not incrementally

The Engine's entire output contract, per ADR-0001, is a set of Engine Events emitted through one seam. `createEngine` will gain an `onEvent: (event: EngineEvent) => void` callback, and `EngineEvent` will be defined as the full union its currently-queued consumers need — `TransitionedEvent` (ticket 03's edge-walk Transition, and ticket 04's Portal Transition, which per its own spec reuses "the same shape of Transition Engine Event") and `InteractedEvent` (ticket 05) — rather than adding one variant per ticket as each lands.

We considered shipping only `TransitionedEvent` now and extending the union when ticket 05 is actually implemented, which is the usual default for an unused type. We rejected it here because all three consumers are already `ready-for-agent`, and their shapes are dictated by `spec.md`'s own "moved, transitioned, interacted" contract rather than guessed at — sizing the type now costs nothing extra and means ticket 05 slots into an existing union instead of widening a type two other call sites already depend on. Detection logic for Portals and Entity Interaction is explicitly out of scope of this decision; only the event shapes are sized ahead of their tickets, not their triggers.
